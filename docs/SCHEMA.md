# Postgres schema

Authoritative as of audit r3 (2026-05-12). Drift-check CI enforces
this against the live `TaskState` definition.

## `tasks`

The hot row — one per task, mutated as the task progresses.

| Column | Type | Notes |
|---|---|---|
| `id` | text PK | 12-hex generated by `uuid.uuid4().hex[:12]` |
| `goal` | text | The user's task string |
| `clarifications` | jsonb | `{question: answer}` from the G9 adaptive flow |
| `workspace` | text | Absolute path on the supervisor host |
| `status` | text | pending / skilling / briefing / executing_loop_N / executing_dag / reviewing_loop_N / escalated / done / failed / interrupted / cancelled |
| `skill_md` | text | Generated SKILL.md (Anthropic skill-creator format) |
| `skill_name` | text | Kebab-case ID parsed from frontmatter |
| `skill_description` | text | Frontmatter description (used for RAG match against skill library) |
| `brief` | text | Executor brief Claude receives as its prompt |
| `result` | jsonb | `{success, summary, next_steps, deliverables, ...}` after final review |
| `started_at` | double precision | epoch seconds |
| `finished_at` | double precision NULL | epoch seconds; null until terminal |
| `cost_databricks_in` | integer | Input tokens spent (orchestrator + reviewer) |
| `cost_databricks_out` | integer | Output tokens spent |
| `cost_claude_usd` | double precision | Estimated Claude executor spend |
| `keep_workspace` | boolean | Skip workspace-TTL cleanup when true |
| `summary_embedding` | vector(1024) | T2 — denormalized for fast `/ask` history search |
| `skill_embedding` | vector(1024) | T2 — denormalized for skill-library RAG match |
| `escalation` | jsonb NULL | T6 — structured escalation payload (kind/summary/why/option_a/option_b/option_abort/auto_resolvable/risk) |
| `escalation_set_at` | double precision NULL | T6 — epoch when supervisor flipped to `escalated` |
| `user_notes` | jsonb NULL | T6b — `["note 1", "note 2"]` from POST /task/{id}/note |
| `corrections` | jsonb NULL | T6b — accumulator of past correction prompts |
| `escalation_answer` | text NULL | T6b — user's answer to a pending escalation |
| `claude_plan` | jsonb NULL | T6b — Claude's plan items (TodoWrite snapshots) |
| `skill_preview` | text NULL | T6b — phase-1 meta-think preview |

Indexes: `idx_tasks_started_at_desc` (recency lookups for /tasks).

## `log_entries`

Append-only event stream — one row per supervisor event. Hot path; batched
inserts via E5 flusher.

| Column | Type |
|---|---|
| `id` | bigserial PK |
| `task_id` | text |
| `ts` | double precision |
| `kind` | text — `phase`, `tool_use`, `tool_result`, `text`, `init`, `final_review`, `env_audit`, `executor_escalated`, `mem0_indexed`, `correction`, `notes_consumed`, `error`, etc. |
| `payload` | jsonb |

Indexes: `idx_log_entries_task_kind` (kind-filtered task queries).

**Common gotcha:** the column is `payload`, not `entry`. Saved to memory
because Claude regularly tries `SELECT entry FROM log_entries` and gets
a `psycopg2.errors.UndefinedColumn`.

## `skill_lessons`

Auto-promoted, frequency-weighted lessons surfaced in every future
orchestrator + reviewer prompt.

| Column | Type |
|---|---|
| `pattern_hash` | text PK |
| `pattern` | text |
| `frequency` | integer |
| `domains` | jsonb — `["code", "research", "writing", "data", "ops"]` subset |
| `remediation` | text |
| `origin_task_id` | text |
| `first_seen` | timestamptz |
| `last_seen` | timestamptz |
| `is_archived` | boolean |

## `langchain_pg_collection` + `langchain_pg_embedding`

LangChain PGVector tables — managed by the library, not us. Holds the
`task_summaries` and `skill_descriptions` collections. `summary_embedding`
and `skill_embedding` columns on `tasks` are denormalized copies for
hot-path lookup (R5 dual-write with rollback on failure).

## `checkpoints` + `checkpoint_blobs` + `checkpoint_writes` + `checkpoint_migrations`

LangGraph PostgresSaver tables — managed by the library. F6
(DAG resume) reads from these.

## Migrations

Applied in order:

1. `postgres_v3.sql` — initial schema (tasks, log_entries, embeddings)
2. `postgres_v3_5_b2_skills.sql` — skill_lessons table
3. `postgres_v2_0_t2_embed_1024.sql` — embeddings 384 → 1024 dim (Databricks gte-large-en)
4. `postgres_v2_0_t6_escalation.sql` — `escalation` + `escalation_set_at` columns
5. `postgres_v2_0_t6b_persist_runtime_state.sql` — `user_notes` / `corrections` / `escalation_answer` / `claude_plan` / `skill_preview` + recency indexes

See [MIGRATIONS.md](MIGRATIONS.md) for the why behind each.
