# Writing template

Use this scaffold for prose deliverables — blog posts, press releases, essays, announcements, internal memos, marketing copy.

## Brief skeleton

- **Objective**: one sentence with the artifact + audience + intent ("opinionated blog post for engineering managers arguing X").
- **Deliverable file(s)**: a single `.md` file with a memorable name (`launch_blog.md`, `q3_memo.md`).
- **What needs to be written / produced**:
  - Audience and tone (opinionated / neutral / instructional / playful).
  - The core argument or message (one sentence).
  - Required sub-points or anchors (3-5 bullets the post must hit).
  - Length target (words or paragraphs — be explicit).
- **Done / acceptance criteria** (numbered, verifiable):
  1. The markdown file exists at the named path.
  2. The piece reads as flowing prose, NOT a bulleted list.
  3. The core argument appears in the first 100 words.
  4. The piece hits all the required sub-points.
- **Constraints**: length cap? avoid first-person? specific style guide?
- **Quality bar**: prose flow over structural cleverness. If a paragraph reads like a bulleted list rephrased, rewrite it.

## Common gotchas (encoded from prior tasks)

- For prose deliverables (blog posts, press releases, narrative essays), do NOT use markdown section headings unless the task explicitly asks for sectioned output. Default to flowing paragraphs.
- Don't pad with rhetorical questions or self-referential meta-commentary ("In this post, we'll explore…"). Cut to the substance.
- Use concrete examples over abstract claims. One specific anecdote beats five generalities.
- The opening sentence carries 80% of the engagement weight — invest in it.
- Adverb-heavy prose ("really", "very", "incredibly") signals weak verb choice. Replace with stronger nouns and verbs.

## Reviewer notes

- Deliverable is the single markdown file.
- Reject pieces that are bulleted lists in markdown clothing.
- Reject pieces that ignore the stated audience (e.g. exec memo written like a fan blog).
